Konsep asas

Apa itu performance testing?

Beban pengguna maya
→
Sistem (SUT) di bawah tekanan
→
Ukur masa tindak balas & kestabilan

Performance testing mengukur sejauh mana sistem laju, stabil, dan boleh berskala apabila banyak pengguna mengaksesnya serentak.

Ia bukan mencari bug fungsi, tetapi bottleneck: response time perlahan, throughput menurun, error % naik, memori/CPU tepu.

Contoh eJPJ: 500 pengguna log masuk & bayar cukai serentak — adakah portal kekal < 2 saat dan 0% ralat?
Performance testingLaju · stabil · berskala
Konsep asas

Jenis ujian prestasi.

Load

Beban dijangka (normal/puncak). Sahkan SLA dipenuhi.

Stress

Tolak melebihi had sehingga patah. Cari titik pecah.

Spike

Lonjakan mendadak pengguna. Pulih semula?

Soak / Endurance

Beban sederhana masa panjang. Cari memory leak.

Scalability

Tambah beban/nod berperingkat. Ukur skala.

Bengkel ini fokus Load & Stress pada eJPJ tiruan, dengan sentuhan Spike & Soak dalam lab.
Jenis ujianLoad · Stress · Spike · Soak · Scalability

Alat kita

Apa itu Apache JMeter?

Apache JMeter ialah perisian open-source yang sepenuhnya berasaskan Java untuk menguji beban dan mengukur prestasi.

Ia menilai functional behavior di bawah beban. Asalnya dicipta untuk aplikasi web — skopnya kini merangkumi API, pangkalan data, FTP, JMS & banyak lagi.

GUI lengkap untuk membina Test Plan; boleh dijalankan tanpa GUI untuk beban sebenar (Hari 1).
Apache JMeterOpen-source · Java · load & performance

PemasanganSet JAVA_HOME jika perlu · guna versi JMeter terkini
Mod operasi

GUI vs non-GUI: guna yang betul.

Mod GUI

Untuk membina & nyahpepijat Test Plan — tambah elemen, lihat View Results Tree, sahkan logik. Berat — jangan guna untuk beban sebenar.

Mod non-GUI (CLI)

Untuk beban sebenar. Guna sumber jauh lebih rendah, boleh hasilkan lebih ramai thread, sesuai untuk CI/CD & pelayan.

jmeter -n -t plan.jmx -l results.jtl
Peraturan: bina dalam GUI, jalankan beban dalam non-GUI. GUI menjejaskan hasil kerana overhead rendering.
GUI vs non-GUI-n = non-GUI · -t = test plan · -l = log hasil
Anatomi Test Plan

Struktur pokok Test Plan.

Test Plan
└─ Thread Group  (bilangan users, ramp-up, loop)
   ├─ HTTP Request Defaults      (Config Element)
   ├─ HTTP Header Manager        (Config Element)
   ├─ CSV Data Set Config        (Config Element)
   ├─ HTTP Request  (Sampler)  — POST /api/log-masuk
   ├─ Constant Timer            (Timer · think time)
   ├─ Response Assertion        (Assertion)
   ├─ Regular Expression Extractor  (Post-Processor)
   └─ View Results Tree         (Listener · debug)
Susunan penting: elemen dinilai atas → bawah; Config & Timer memberi kesan kepada semua Sampler dalam skopnya.
AnatomiThread Group · Sampler · Config · Timer · Assertion · Listener · Pre/Post-Processor

Langkah 1

Thread Group: model beban anda.

Number of Threads

Bilangan pengguna maya serentak. Cth 100 = 100 pengguna.

Ramp-Up Period

Masa (saat) untuk lancar semua thread. 100 thread / 50s = 2 thread/saat.

Loop Count

Berapa kali setiap thread ulang Sampler. Boleh set Infinite + jangka masa.

Ramp-up beransur elak "thundering herd" — beri sistem masa memanas (warm-up) dan lebih realistik.
Thread GroupUsers × Ramp-Up × Loop = corak beban
Langkah 2

HTTP Request Sampler.

Medan utama

  • Protocol: http / https
  • Server Name / IP: localhost
  • Port: 3000
  • Method: GET / POST
  • Path: /api/log-masuk
  • Body Data: JSON payload

HTTP Request Defaults

Letak Protocol/Server/Port sekali dalam Config Element ini — semua Sampler mewarisinya. Tukar server (staging↔local) di satu tempat sahaja.

{ "no_kp": "${no_kp}",
  "kata_laluan": "rahsia123" }
HTTP RequestPath relatif · Defaults tanggung host/port
Config Elements

Config Element yang wajib tahu.

HTTP Header Manager

Tetapkan header semua permintaan — cth Content-Type: application/json, Authorization: Bearer ${token}.

HTTP Cookie Manager

Simpan & hantar cookie sesi automatik antara permintaan — perlu untuk aliran log masuk berasaskan sesi.

HTTP Cache Manager

Tiru gelagat cache pelayar (304 Not Modified) supaya beban lebih realistik.

HTTP Request Defaults

Nilai lalai host/port/protocol untuk semua Sampler — elak ulang.

eJPJ: Header Manager bawa Content-Type: application/json + X-CSRF-Token: ${csrf}; Cookie Manager kekalkan sesi log masuk.
Config ElementsHeader · Cookie · Cache · Defaults
Langkah 3

Listeners: lihat hasil (berhati-hati).

View Results Tree

Setiap permintaan/respons penuh. Debug sahaja — sangat berat, matikan semasa beban.

Summary Report

Ringkasan agregat: sampel, purata, min/max, throughput, error %.

Aggregate Report

Tambah percentile (90/95/99) & median — lebih berguna untuk SLA.

Amaran: semua GUI listener menggunakan memori besar. Untuk beban sebenar, matikan listener & guna fail .jtl + laporan HTML non-GUI.
ListenersGUI listener = debug · beban sebenar = .jtl
Langkah 4

Parameterize dengan CSV Data Set Config.

# pengguna.csv
no_pendaftaran,no_kp
WXY1234,880101015500
WABC88,900202025511
JKL4567,910303035522

Set Filename = pengguna.csv, Variable Names = no_pendaftaran,no_kp. Setiap thread ambil baris berlainan.

Rujuk dalam Sampler: /api/kenderaan?no_kp=${no_kp}. Set Recycle on EOF & Sharing mode ikut keperluan.

Elak semua pengguna maya hantar data sama — data realistik = ujian realistik.
CSV Data Set ConfigData unik per thread · no_pendaftaran / no_kp
Langkah 5

Assertions: sahkan respons betul.

Response Assertion

Sahkan kandungan/kod respons. Cth: Response Code = 200, atau Text Response mengandungi "token". Gagal → sampel ditanda ralat.

Duration Assertion

Sahkan respons tiba dalam masa maksimum (cth < 2000 ms). Melebihi → ditanda gagal walaupun kod 200.

Tanpa assertion, JMeter kira HTTP 500 sebagai "berjaya" (permintaan dihantar). Assertion menjadikan kejayaan bermakna — sahkan kandungan, bukan hanya penghantaran.
AssertionsResponse Assertion · Duration Assertion
Langkah 6

Timers: tambah think time.

Constant Timer

Jeda tetap (cth 1000 ms) antara setiap permintaan.

Uniform Random Timer

Jeda rawak seragam dalam julat — lebih semula jadi.

Gaussian Random Timer

Jeda rawak taburan normal sekitar nilai purata.

Pengguna sebenar tidak klik tanpa henti. Think time mengelak beban tak realistik & melindungi SUT daripada dibanjiri secara buatan. Pasangan penting: think time + pacing.
TimersConstant · Uniform Random · Gaussian Random

Konsep penting

Correlation: kenapa main balik gagal.

POST /api/log-masuk
→
Respons: token + csrf (dinamik)
→
Rakam & guna semula = GAGAL

Nilai seperti token & csrf dijana baharu setiap sesi. Jika kita "hardcode" nilai lama, pelayan menolak (401/403).

Correlation = ekstrak nilai dinamik daripada satu respons, simpan ke pemboleh ubah, dan guna semula dalam permintaan berikutnya.

Aliran eJPJ: log masuk → ekstrak token & csrf → guna dalam POST /api/kenderaan/:no/bayar-cukai.
CorrelationNilai dinamik mesti diekstrak, bukan hardcode
Post-Processors

Tiga cara ekstrak nilai.

JSON Extractor

Untuk respons JSON. Guna JSONPath, cth $.token → simpan ke token.

Regular Expression Extractor

Corak regex atas teks mentah, cth "csrf":"(.+?)" → group 1.

Boundary Extractor

Tetapkan teks kiri & kanan nilai — mudah, tanpa regex rumit.

// JSON Extractor
JSON Path expressions:  $.token      → token
                        $.csrf       → csrf
// Guna semula:  Header  X-CSRF-Token: ${csrf}
//               Header  Authorization: Bearer ${token}
ExtractorsJSON ($.token) · Regex · Boundary
Struktur ujian

Logic Controllers.

Transaction Controller

Kumpul beberapa Sampler jadi satu transaksi — ukur masa hujung-ke-hujung (cth "Bayar Cukai").

If Controller

Jalankan anak elemen hanya jika syarat benar — cth ada saman belum bayar.

Loop Controller

Ulang blok bilangan kali tetap dalam satu iterasi thread.

Throughput Controller

Kawal peratus pelaksanaan — cth 30% pengguna bayar saman.

Transaction Controller amat berguna: satu baris hasil "Log Masuk → Semak → Bayar" dan bukan tiga baris berasingan.
Logic ControllersTransaction · If · Loop · Throughput
Scripting & fungsi

JSR223 (Groovy) & JMeter functions.

JSR223 Sampler / Post-Processor

Tulis logik tersuai dalam Groovy — jana data, ubah pemboleh ubah, kira tandatangan. Groovy paling laju & disyorkan.

// JSR223 PostProcessor (Groovy)
def body = prev.getResponseDataAsString()
def json = new groovy.json.JsonSlurper().parseText(body)
vars.put("token", json.token)

Fungsi terbina

  • ${__Random(1,1000)} — nombor rawak
  • ${__UUID} — ID unik
  • ${__time(yyyy-MM-dd)} — cap masa
  • ${__P(threads,50)} — baca property CLI
JSR223 / functionsGroovy · __Random · __UUID · __time · __P

Skala beban

Ujian teragih (master–slave).

Satu mesin sukar hasilkan beban sangat tinggi. Distributed testing agih thread ke beberapa nod slave, dikawal satu master.

Master kumpul hasil semua slave. Guna bila perlu ribuan pengguna maya melebihi had CPU/rangkaian satu mesin.

Ringkas untuk bengkel — konsep sahaja. Alternatif moden: jalankan JMeter dalam kontena/awan.

Automasi & pemantauan

CI/CD + live monitoring.

CI/CD integration

Jalankan JMeter non-GUI dalam Jenkins atau GitHub Actions pada setiap rilis. Gagalkan pipeline jika SLA dilanggar (error % / percentile ambang).

- run: jmeter -n -t plan.jmx \
    -l out.jtl -e -o report/

Live monitoring

Backend Listener hantar metrik ke InfluxDB, dipapar langsung dalam Grafana semasa ujian berjalan — nampak throughput & ralat secara masa nyata.

Ringkas untuk bengkel. Matlamat: ujian prestasi jadi sebahagian pipeline, bukan aktiviti sekali sahaja.
CI/CD & monitoringJenkins / GitHub Actions · Backend Listener → InfluxDB → Grafana
Amalan terbaik

Amalan terbaik & jerangkap biasa.

Buat

  • Jalankan beban dalam non-GUI, matikan GUI listeners.
  • Tambah think time & pacing yang realistik.
  • Ramp-up beransur + warm-up sistem.
  • Parameterize data (CSV) — elak nilai sama.
  • Simpan Test Plan dalam version control.

Elak

  • Jangan uji produksi — guna mock/staging.
  • Jangan biar GUI listener aktif semasa beban.
  • Jangan hardcode token/csrf — gunakan correlation.
  • Jangan hantar semua thread serentak tanpa ramp-up.
  • Jangan percaya purata sahaja — semak percentile.
Best practicesNon-GUI · think time · ramp-up · parameterize · version control
